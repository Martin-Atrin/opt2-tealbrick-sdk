# @opt2-tealbrick/miniapp-sdk

Server runtime for opt2 miniapps (SDK-API §3–§13): `defineApp({ manifest, handlers, hooks?, dynamic?, publicRoutes?, migrations, onStart?, onStop?, events?, jobs?, attention?, pendingCount? })` + `startApp(app, process.env)`. The SDK mounts every route from the manifest (`/tb/v1/ops/:op`, hooks, bridge ops, person session under `/a/<product>/`, health), verifies grants and call proofs, runs `authorize()`, owns the one store (node:sqlite under `TB_DATA_DIR`), receipts/holds, idempotency, scopes (manifest default grants), audit, keys (`getKey`: app-own > workspace default via the bridge), app secrets (`ctx.secrets`, sealed under `TB_KEK`), claim via the bridge, slice refresh, `callServiceHelper`, and (0.1.21) the ONE background job runner: `ctx.jobs` (leased, resumable ticks with checkpoints, retries, pause/resume/cancel per job and per app, restart drain) and `ctx.schedule` (scheduled ops that re-run `authorize()` at fire time with the stored caller). Apps do not write their own schedulers (SDK-API §19). (0.1.23, SDK-HV-1) A dynamic op may add `holdView(tool, args, ctx)`: the SDK awaits it (5 s budget) when a call is held and shows its plain-text view to the owner; a failure shows the default view plus "Tealbrick could not read the content of this request." and never blocks the hold; the approval is bound to sha256(view), so a changed upstream content is held again (SDK-API §4.6).

0.1.1 adds: backups/restore/export (§7.3, ustar+gzip, cron), the React client (`@opt2-tealbrick/miniapp-sdk/client`: `TbProvider`, `useSession`, `useHolds`, `useScopes`, `useAgents`, `tbFetch`, `callOp`), and the `tb-exec` bin (`tb-exec [--manifest <path>] [--helper-cmd "<cmd>" --helper-target 127.0.0.1:<port>] -- <upstream...>`; default manifest path `/opt/tb/tealbrick.manifest.json`).

0.1.3 adds the `tb-gen` bin: `tb-gen openapi | kit [--build] | docs | railway | check | all [--manifest <file>] [--out <dir>]` — generated from the manifest, deterministic; `check` is the drift check (CONFORMANCE M4).

Next release adds (C53):

- **One privilege drop (BSA-05).** When `startApp` or `tb-exec` starts as root (Railway mounts volumes root-owned, C38), it creates and `chown -R`s `TB_DATA_DIR` (and `TB_BACKUP_DIR` when it lies outside it) to uid/gid 1000, clears supplementary groups, then calls `setgid(1000)` and `setuid(1000)`. This happens before the store, keys, children or any listener open. If the ids do not read back as 1000, boot fails with `privilege_drop_failed`. When the process is not root, nothing happens. The `tb-exec` upstream and helper children inherit uid 1000. Apps and images must not add their own drop.
- **Auto idempotency key (BSA-12).** `GET /a/<product>/tb/v1/session` now also answers `idempotencyRequired: string[]`: the person-audience op ids whose manifest says `idempotency: "required"` (additive field). The client `callOp` sends a fresh `crypto.randomUUID()` key for those ops when the caller passes none; a caller key always wins. The auto key is per call and `callOp` never retries. To retry the same logical call safely, pass your own `idempotencyKey` and reuse it on the retry.
